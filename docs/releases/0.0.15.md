# 0.0.15 cohort: terminal charts and diagrams

**Release test passed; not yet published.** Every workstream in the
[0.0.15 plan](../plans/0.0.15.md) is merged and the release test below
passed on the integrated tree. Publication follows the steps under
[Publication](#publication).

0.0.15 draws data and structure in the terminal, natively:

- **Charts you compose**, in `rich_ext::chart`: sparklines, horizontal and
  vertical bars, histograms, Braille line and scatter charts, gauges and
  bullet charts, heatmaps, status matrices, KPI cards and timelines. Each
  is a renderable that measures itself, fits the width it is given, sits in
  a `Table`, `Panel`, `Layout` or `Live`, has an ASCII form, and reads
  without colour.
- **Diagrams**, in a new crate, `rs-rich-diagram`: a graph model, the
  layered layout lifted out of Mermaid (which now draws through it), a
  builder API, and a parser for the DOT (Graphviz) subset people write by
  hand, with a `dot` fence renderer and an optional Graphviz backend.
- **Sources:** Cargo dependency trees (`rich deps`, with `--why` and
  `--graph`) and JSON Schema trees and diffs (`rich schema`).
- **From the shell and Python:** `rich chart` draws CSV, JSON or a pipe;
  `rich dot` draws DOT; `rs_rich.chart` and `rs_rich.diagram` bind it all.
- **0.0.14's known limits fixed:** `:micro:` markup in titles, captions
  and Markdown; real graphics in `rich asset --kind micro` and
  `rich explore --icons`; every built-in component rebindable.

A default build of `rs-rich` is unchanged, still 0.0.9, and still renders
exactly like upstream `rich` 15.0.0.

## Migration

- **Charts, diagrams and Mermaid no longer end with a blank line.** Every
  `rich_ext::chart` renderable, `rich_diagram::{Diagram, Dot}` and
  `rich_mermaid::Mermaid` used to end its last line with its own newline,
  so `print` left a blank line after it. They now leave that newline to
  `print`, like core's renderables, and an empty chart prints nothing.
  Output that relied on the blank line has one line fewer.
- **Mermaid's flowchart types are re-exports.** `flowchart::{Direction,
  Shape, Node, Edge, Stroke, Head}` are `rich_diagram`'s types (same
  variants and fields) and `layout::Diagram` is an alias of
  `rich_diagram::Drawing`.
- **Limits on drawn graphs.** `rich_diagram::layout::draw` refuses more than
  2,000 edges or 5,000 nodes before laying out, and DOT sources are capped
  at 64 KiB, 500 nodes, 2,000 edges and 64 levels of nesting, with an error
  naming the limit (Mermaid's caps, now shared).
- **Keymaps:** a rebound or installed key now takes precedence over an
  earlier action's declared key in the same context, instead of being
  ignored. `FilePicker::rebind` sends its own actions (`open`, `up`,
  `hidden`) only to the picker; use `select.<action>` for the list's.
- **`--watch` keeps the `:micro:` fallback**, single file or several.
- **`rich deps` clears `RUSTC_WRAPPER` and `RUSTC_WORKSPACE_WRAPPER`** (and
  their `CARGO_BUILD_` forms) when it runs `cargo metadata`; see
  [Running Cargo](../guide/ext/sources.md).

## Release test (2026-10-05)

RESULTS_TABLE

### What the release test found and fixed

Three independent audits covered the whole 0.0.15 delta: the charts,
`rich chart` and `rs_rich.chart`; the diagram crate, DOT, `rich deps` and
`rich schema` (correctness and security); and the 0.0.14 follow-ups with
every place the trailing-newline change could affect layout. They found 27
issues. Each was reproduced first, then fixed with a regression test that
failed (or aborted, or hung) before the fix. The main ones:

- **Denial of service from small inputs.** About 20 KB of nested DOT
  braces overflowed the stack and aborted the process (the CLI, a
  ```` ```dot ```` fence in Markdown, and Python's `parse_dot`); a 6 KB
  DOT cross product expanded to 360,000 edges and hung the layout; a 3 KB
  JSON Schema whose `$ref`s fan out down a chain grew the tree and the
  diff exponentially; and an `additionalProperties` chain reset the
  diff's depth guard. DOT now has nesting, size, node and edge limits
  checked while groups expand, the layout refuses oversized graphs before
  working, and schema trees and diffs have budgets that say when they stop.
- **`rich deps` in workspaces.** A workspace member reached through another
  member lost its dev-dependencies, depending on member order, so on this
  repository `--why trybuild` printed nothing; members appeared as `(*)` at
  the top level; deep chains overflowed the stack; and `--why` printed
  nothing (exit 0) when the chosen kinds reached no match. `rich deps` also
  ran a project's configured `rustc` wrappers through `cargo metadata`.
- **Charts with large values.** Years, timestamps and other values of 1,000
  and up on a short span were squashed onto a `2.0k` axis; histogram edges
  were written as duplicates (`[1.0k, 1.0k)`) and a value on an edge was
  counted in the bin whose label excludes it. Labels the compact form
  cannot write exactly are now written in full, and edges are exact.
- **Crashes:** `ValueFormat::Fixed` with 65,536 or more decimals panicked
  (reachable from Python); huge widths and heights overflowed or allocated
  without bound; ranges spanning ±1e308 collapsed to NaN labels.
- **`:micro:` in Markdown** was drawn inside indented code blocks, fences in
  quotes and list items, and code spans across lines, and replaced tokens
  in link and image URLs. Code and link ranges now come from the Markdown
  parser itself.
- **Behaviour:** `rich chart` turned `1e400`, `nan` and `inf` into silent
  gaps and dropped cells past the header; `Confirm` no longer answered a
  lowercase press for an uppercase choice key (a regression from 0.0.14);
  rebinding `FilePicker`'s `up` moved the list's cursor key; a rebound key
  held by an earlier action was ignored; single-file `--watch` drew micro
  images; DOT ignored `\E`, `\T` and `\H`, mis-lexed numerals and refused a
  comment before `=`; ASCII consoles got `…`, `×` and `µ` in notes and
  legends; a non-finite KPI delta read `▲ +-`.

The docs were refreshed across the README, the guides, the Python pages,
the crate READMEs and `AGENTS.md`'s dependency graph, and the refresh found
two CLI slips that are fixed: `rich doctor` did not report the `record`,
`interact` and plugin-loading features, and `--help` did not list `.mmd`,
`.mermaid`, `.dot` and `.gv` among the auto-detected types.

### Known limits

- **DOT clusters** are drawn without their frames (the layout cannot draw
  them yet; a note names them, as Mermaid does for subgraphs). `rank`
  constraints are ignored, and invisible and outline-free (`plaintext`,
  `none`) nodes are drawn as boxes, with a note.
- **`rich deps` runs Cargo** in the target directory, so that project's
  Cargo configuration still applies (other than the `rustc` wrappers,
  which are cleared), including index fetches. `--metadata FILE` runs
  nothing.
- **Large schemas** stop at 10,000 tree entries or diff changes, with a note.
- **A narrow line chart** can drop an x-axis label between its first and
  third, because the first label is pinned to the left edge.
- **Rustdoc links** to feature-gated items (plugin loading, `Diagnostic`
  adapters, the `rich_println` macros, `rich_diagram`'s `plugin` and
  `graphviz` items) render as plain text in a default-features build.
- **Real graphics terminals.** As in 0.0.14, the PTY tests check the bytes
  and cells around every protocol but not the images; the pickers now draw
  them too. See [Before publishing](#before-publishing).

## Before publishing

One check cannot run in CI: open the graphics paths in a real terminal.

```bash
RICH_MICRO=kitty rich asset --kind micro          # Kitty or WezTerm: images in the picker
RICH_MICRO=kitty rich explore --icons .           # icons in the explorer
printf '# Build :micro:status/success:\n\n`:micro:fun/cat:` stays text\n' | rich -m -
rich --panel --title 'Deploy :micro:status/success:' -p done
```

Each should draw the images in their cells, leave the code span as text,
and leave nothing behind after the command ends or Ctrl+C.

## Publication

`RELEASES.toml` lists every package's version in publication order. Tag what
is due on the merged commit on `main`:

```bash
python3 scripts/release_cohort.py status          # what is published, tagged, or due
python3 scripts/release_cohort.py tag --dry-run   # what it would tag
python3 scripts/release_cohort.py tag             # tag and wait, one at a time
```

`tag` skips the five packages already on crates.io and pushes one annotated
tag at a time, waiting for each version to appear on its registry before
the next:

1. `rs-rich-diagram-v0.0.1`, the new crate, then its Trusted Publishing entry;
2. `rs-rich-mermaid-v0.0.4`;
3. `rs-rich-ext-v0.0.13`;
4. `rs-rich-micro-v0.0.2`;
5. `rs-rich-record-v0.0.3`;
6. `rs-rich-interact-v0.0.3`;
7. `rs-rich-cli-v0.0.15`;
8. `python-v0.0.4`.

crates.io offers Trusted Publishing only on a crate that already exists, so
`rs-rich-diagram` 0.0.1 uploads with the `crates-io` environment's
`CARGO_REGISTRY_TOKEN`: the workflow sees that the crate is new and uses it
for that upload only. See
[Registry authentication](../BRANCHING.md#registry-authentication-trusted-publishing).
