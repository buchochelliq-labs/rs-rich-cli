# 0.0.22 cohort: parity, the plugin marketplace and a terminal web browser

![Memo, intuiTUIve's elephant, in the cartoon look](../assets/intuituive/mascot/memo-cartoon.svg){ .tui-mascot width="128" }
**To be published** by one release run, `release-0.0.22`, with `rs-rich`
0.0.10 on PyPI. See [Publication](#publication).

0.0.22 finishes stage 2 of the [plan to 1.0.0](../plans/1.0.0.md). The
core's promise, "renders what `rich` renders", is now checked row by row:
every widget, live display and document module is ported or recorded as a
divergence, `scope.py` is ported, and every divergence has a verdict. The
plugin marketplace ships end to end, from a signed index to
`rich plugin install`. intuiTUIve gains what three demo clones shared and
four controls whose labels and options change while they are shown, and a
new crate, [Noctiluca](../guide/noctiluca.md), is a web browser for the
terminal built on them. The [0.0.22 plan](../plans/0.0.22.md) says what
moved on to [0.0.23](../plans/0.0.23.md).

- **Parity with rich 15.0.0.** Twelve rendering-core rows, the widget and
  layout rows (`padding`, `panel`, `align`, `constrain`, `table`, `layout`,
  `screen`, `bar`, `box`, `_ratio`), the live display rows (`live` with the
  alternate screen and the stdout/stderr redirect, `progress`, `status`,
  `spinner`, `file_proxy`) and the document rows are complete in
  [PORTING](../PORTING.md), with 34, 47 and 86 new golden cases
  (`parity_core.tsv`, `parity_widgets.tsv`, `parity_docs.tsv`) and
  `parity_live.tsv`. `scope.py` is ported (`render_scope`), and so is
  `pretty.py`'s layout over a description of the Python object.
  `console.py` is the one library row still partial; PORTING lists what it
  lacks.
- **Every divergence has a verdict.** [DIVERGENCES](../DIVERGENCES.md)
  opens with a table: seven entries resolved in this release, the rest
  permanent, each with its reason.
- **The differential fuzzer covers the documents.** `scripts/diff_rich.py`
  also generates Markdown, Tree, Columns, Progress frames, Pretty and JSON
  cases. Its first runs found six Markdown families, all fixed; one case
  remains a known divergence,
  [#769](https://github.com/buchochelliq-labs/rs-rich-cli/issues/769). See
  [Parity](../parity.md).
- **rs-rich-marketplace 0.0.1 (new).** The marketplace client: it verifies
  the index's minisign signature, key chain, serial and expiry, reads
  listings, resolves a version against the host's plugin API and ABI, and
  installs over HTTPS within the declared size and SHA-256, with a
  lockfile. No terminal code. See [Plugins](../PLUGINS.md).
- **`rich plugin`.** `search`, `info`, `install`, `update`, `remove`,
  `list`, `enable`, `disable` and `verify`; `rich plugin browse`, the same
  in a selector with each package's provenance; and `rich plugin publish`,
  which checks a package and writes its listing for a pull request. An
  installed, enabled WASM plugin loads on every run without `--plugin`.
  `install` shows the tier, the capabilities and the permissions and asks
  before it writes anything.
- **WASM plugins on by default.** rs-rich-cli's `wasm-plugins` feature is a
  default, so a default `rich` loads sandboxed WASM plugins. Native plugins
  stay off by default.
- **The signing workflow and the compatibility job.** The marketplace
  repository's workflow (rebuild the index, bump the serial, sign in a
  protected environment) is in `docs/marketplace-repo/`; CI installs the
  official plugins and a fixture WASM plugin from a test marketplace.
- **The gaps three clones shared.** Panel titles flush with the corner and
  plain-text titles ([Panels](../guide/intuituive/panels.md)), a tree table
  ([Tables](../guide/intuituive/tables.md)), `App::min_size` with a node of
  its own or shorter forms of its message, and scope cycling that reveals a
  hidden pane. The clones drop their workarounds.
- **Live controls.** Labels that change in place (`button_of`,
  `checkbox_of`, `switch_of`), a three-state check box (`CheckState`),
  select and radio options known by key with a disabled reason, and a live
  action list: help and the palette update while open, and running a
  binding checks it again. See
  [Buttons and form controls](../guide/intuituive/controls.md).
- **Made-up releases with two holds.** `App::synthesize_releases_with`
  takes `Holds { first, repeat }`, so a game holds a key across the
  keyboard's repeat delay: rs-rich-doom's core gap 4.
- **Noctiluca 0.0.1 (new), a terminal web browser.** A page opened in a
  sandboxed headless Chrome, drawn in an intuiTUIve app: Chrome's layout
  snapped to cells, or reader mode; forms as stock intuiTUIve widgets, link
  hints, an address bar with keywords, back and forward, find, bookmarks,
  per-site keys and the F1 overlay of every action. Sound is off unless
  asked. Its [docs](../guide/noctiluca.md) cover installing, keys, config
  and what works today. rs-rich-embed gains `DevTools::call` and `listen`,
  and switches for audio, downloads and a kept profile, all off by default.
- **Memo in the cartoon look, and a spot for every crate.** Each crate's
  README and the crate tables show Memo with a prop that says what the
  crate does.
- **The recorder.** A tape writes an APNG only when its `Output` line or
  `--format` names it (0.0.22's decision 2), and a late read keeps a frame
  for each update inside it. macOS still keeps fewer frames: a
  [known issue](../known-issues.md#the-recorder-keeps-fewer-frames-on-macos).

A default build of `rs-rich` still renders exactly like upstream `rich`
15.0.0, now against many more golden cases than before.

## Migration

Breaking changes in 0.0.x crates (the
[CHANGELOG](https://github.com/buchochelliq-labs/rs-rich-cli/blob/main/CHANGELOG.md)
has each):

- **New public fields.** A struct literal of these needs the new field:
  `rich_interact::Binding` and `rich_interact::Command` (`unavailable:
  None`), `rich_intuituive::AccessState` (`mixed: false`) and
  `rich::r#box::Box` (`ascii`). Their constructors and builders are
  unchanged, and `AccessState` is `Default`.
- **`rich::RichError` has new variants** (`Console`, `Style`,
  `MissingStyle`, `StyleStack`, `NotRenderable`, `Live`): an exhaustive
  `match` needs arms for them, or a wildcard.
- **`wasm-plugins` is a default feature of rs-rich-cli.** A build that
  must not carry the WASM runtime names its features with
  `default-features = false`.
- **Rendering that now matches upstream** (each was a recorded
  divergence or a parity gap):
  - a renderable without its own `measure` measures as `(0, max_width)`,
    so `Columns` and `Markdown` in a table cell size as upstream sizes
    them;
  - a printed `Screen`, a printed `LiveRender` and a titled `Rule` whose
    `end` has no newline end without a line break
    (`Renderable::print_end_line`, which defaults to `true`);
  - a zero `height` on `Panel` and `Align`, and a zero `width` on `Align`,
    is read as unset; `Constrain` with a zero width renders nothing;
  - `Text::from_markup` replaces `:emoji:` codes; `AnsiDecoder` drops
    private escapes and splits lines as rich 15.0.0 does;
  - paging drops hyperlinks unless asked (`Console::page_with_links`);
  - prompts parse numbers as Python does and take the default only for an
    empty answer.
- **Tapes:** a tape with no `Output` line no longer writes an APNG. Add
  `Output apng` (or `--format apng`) to keep one.
- **Behaviour:** running a binding from intuiTUIve's palette checks its
  condition again, so a command that stopped applying after the palette
  opened no longer runs.

To be filled in from the release PR's validation.

### Not in this release

- **`console.py` stays partial.** PORTING lists what it lacks (`log`,
  `status`, the `screen()` context, capture, `record=`, render hooks, size
  setters and the colour system from the environment, among others).
- **One fuzzer case** remains a known divergence:
  [#769](https://github.com/buchochelliq-labs/rs-rich-cli/issues/769), an
  ordered Markdown item holding only an empty link under `justify="full"`.
- **The recorder's frame rate on macOS** is still not fixed; the
  frame-rate test keeps its lower bound on Linux only.
- **The marketplace's official keys** are not compiled in yet: until they
  are, `--marketplace-keys` or `RICH_MARKETPLACE_KEYS` names the keys to
  trust.
- **Moved to [0.0.23](../plans/0.0.23.md)** by the maintainer:
  rs-rich-doom's core gaps (all but gap 4), the `rich-rst` 2.2.0 pin, and
  Memo's illustrations revisited.
