# 0.0.26 cohort: Noctiluca made steady, before the API review

![Memo, intuiTUIve's elephant, in the cartoon look](../assets/intuituive/mascot/memo-cartoon.svg){ .tui-mascot width="128" }
**To be published** from `main` by one `release.yml` run on rab v2.1.1
(tag `release-0.0.26`), with `rs-rich` 0.0.14 on PyPI.

0.0.26 is one more release before 0.1.0, the API review
([the 1.0.0 plan](../plans/1.0.0.md), decisions 15 and 16). It ships what
merged after 0.0.25 (#877, #878, #886) together with the fixes they
needed (#887, #888), so the review starts from a steady base. The
[0.0.26 plan](../plans/0.0.26.md) lists every item and the maintainer's
calls.

- **Noctiluca plays video at about 24 frames a second on a page that keeps
  changing.** Before (on `main` at `b8ce24e2`, after #878), a page whose
  clock and progress bar kept ticking got about one frame a second in
  every protocol. Each change asked for a
  page reading, and frames stopped while it waited.
  - Readings the page asks for now wait three times their cost, and at
    least a second while a video plays. Readings you cause never wait.
  - Frames go on while a reading waits.
  - The screencast covers only the playing region.
  - Waiting pages coalesce to the newest.
  - Kitty frames are compressed.

  [The measurements](../design/noctiluca-youtube-perf.md):

  | Watch page, 120×40 | Before (`b8ce24e2`) | 0.0.26 |
  |---|---|---|
  | Kitty frames/s | 0.9 | 24.3 |
  | iTerm2 frames/s | 0.4 | 21.2 |
  | Half blocks frames/s | 0.7 | 25.2 |
  | Twitch, Chrome CPU | 52% | 35% |
- **#883: the iTerm2 video gate passes.** #878's
  [performance qualification](../design/noctiluca-performance-qualification-f309073.md)
  found its iTerm2-compatible gate failing. It now passes 3 of 3 runs with
  its thresholds and workload unchanged: p95 8.65–8.86 ms (limit 13.670)
  and p99 8.85–9.49 ms (limit 15.734). Kitty and ANSI still pass 3 of 3.
  The changes:
  - rs-rich-art's own resampler gives `image`'s Lanczos3 and Triangle
    pixels byte for byte, resampling only what a crop keeps;
  - rs-rich-ext's painter writes a picture's tagged cells from their
    colours;
  - fewer copies per frame.
- **Sound is on by default** when Noctiluca runs on your own machine. It
  is off over SSH (`SSH_CONNECTION` or `SSH_TTY` set), where Chrome's
  sound would play on the far machine. `--audio` turns it on there, and
  `--mute` (or `--no-audio`) turns it off anywhere.
- **Media and adaptive layouts (#878):**
  - source-layout preservation;
  - steadier media updates;
  - bounded image retries;
  - shared measured popups;
  - configurable controls;
  - canvases polled during DOM updates.

  The [images guide](../guide/intuituive/plugins.md#images-art) covers intuiTUIve's
  `ImagePresentation`.
- **Premeasured cells (#877):** `Screen::write_premeasured` and
  `Canvas::write_premeasured` import a grid of cells whose widths the
  caller measured, painted on fullscreen terminals. `Cell.width` is now
  `u16` (see [Migration](#migration)).
- **Fixed:**
  - the reader view's stale cells: a scroll view inside a `layers` stack
    now clears what it no longer draws;
  - an inline app now restores the terminal when its last repaint fails;
  - a hint pressed while Chrome applies new viewport metrics no longer
    fails with "The page is not ready.";
  - wrapping action labels keep source order: `[Send]` comes before
    `[Unavailable]`;
  - a skip link parked above a top bar is no longer drawn;
  - one trace, `NOCTILUCA_TRACE=FILE`, replaces stderr output that
    corrupted the display.
- **The nightly differential parity run is green again.** It had failed
  on Markdown cases since 2026-10-26. The fixes are pinned by goldens
  `markdown_fuzz_10` to `30`, and the last known case (#769) is among them.
  Upstream rich's own dependencies are pinned for the parity jobs
  (`scripts/upstream-oracle-constraints.txt`), since markdown-it-py 4.3.0
  changed a quirk [DIVERGENCES §54](../DIVERGENCES.md) records.
- **Releases run on rab v2.1.1.** A crate's release record no longer lists
  the files of a same-named PyPI package.

A default build of `rs-rich` still renders exactly like upstream `rich`
15.0.0.

## Migration

The [CHANGELOG](https://github.com/buchochelliq-labs/rs-rich-cli/blob/main/CHANGELOG.md)
has each breaking change, and `api/semver-breaks.toml` lists them with
their reasons:

- **rs-rich-ext, rs-rich-intuituive:** `Cell::width` is `u16`, formerly
  `u8`. `Cell::new` keeps its `u8` argument.
- **noctiluca:** `Args` gains `mute`, and the test-only `FakeState` gains
  `screencast_area` and `screencast_areas`. A struct literal adds them or
  uses `..Default::default()`.
- **Noctiluca's sound default:** a script that relied on Chrome starting
  muted passes `--mute`.

### Noctiluca on real sites

Walked on 2026-11-10 at 120×40, once with `--images kitty` and once with
`--images ansi`. It used a release build and headless Chromium 153, in a
PTY with a capturing terminal. Where a fault showed, the same steps were
run on 0.0.25 (`noctiluca-v0.0.4`). **Nothing found blocks the tag.**
Every fault was also seen on 0.0.25 or was not checked there, nothing
crashed or hung, and nothing was sent without asking.

| Site | Result |
|---|---|
| BBC News, front page and an article | Pictures in place, captions from alt text, reading order, reader mode, long-page scrolling: all worked. A caption loses its first letter where it meets the photo above (#880) |
| A video page (Wikimedia Commons' *Big Buck Bunny*; YouTube shows its bot wall, #791) | Poster and play mark, frames while it plays (about 14 a second on this network), seek, mute and pause all worked. The page's `[ Play video ]` button is new since 0.0.25. After a pause, the media keys pick a source-less `<video>` (#889) |
| Twitch, a quiet and a busy channel | About 20 frames a second against 1 to 16 on 0.0.25. On a busy channel frames stop after 12 to 25 s (#890), the chat log stalled in one run (#891), and `{` blanks the log instead of holding it (#892). 0.0.25 does all three |
| MDN, `Array.prototype.map()` and `<table>` | Code blocks, tables, nested lists, hints, find in page, back and forward all worked. CodeMirror examples read as one line, and in-page links do not scroll |
| NixOS Discourse, a thread and the search page | Avatars, code blocks and paging worked. A field draft stayed a draft (`● edited · Enter applies`) until Esc dropped it. `G` lands at row 1 after Discourse re-renders its posts |

The faults go to 0.0.27: #889 to #892, the layout faults under #879 and
#880, and the smaller ones in the 0.0.26 plan's follow-ups.
