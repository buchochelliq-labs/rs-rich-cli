# 0.0.24 cohort: Cornacai, Textual parity, and Noctiluca for scripts and agents

![Memo, intuiTUIve's elephant, in the cartoon look](../assets/intuituive/mascot/memo-cartoon.svg){ .tui-mascot width="128" }
**Published on 2026-11-03**, every crate by one release run, with `rs-rich`
0.0.12 on PyPI. See [Publication](#publication).

0.0.24 opens the two tracks to 1.0.0 that the maintainer set on 2026-10-27
([the 1.0.0 plan](../plans/1.0.0.md)): the apps, and the stable set's
groundwork. It landed in four waves of parallel work (#828 to #841). The
[0.0.24 plan](../plans/0.0.24.md) has every item and what moves on.

- **Cornacai** (new): a terminal client for coding agents that speak the
  Agent Client Protocol. It streams the agent's Markdown and folds its tool
  calls into cards. It asks before a permission or a command, and you
  review each edit in a diff view, whole or hunk by hunk. It has `@` file
  mentions, several sessions as tabs and a shell pane. Its protocol layer
  is the new **rs-rich-acp** crate, an ACP v1 client with a replaying fake
  agent for tests. See [Cornacai](../guide/cornacai.md).
- **intuiTUIve catches up with Textual.** It gains:
  - a streaming Markdown widget, a Markdown viewer and a diff view;
  - Textual's 21 themes on a semantic `Palette`;
  - user keymaps, and command palette providers with system commands;
  - modes, screen results and a pane you can maximize;
  - Pilot-style test helpers, and screenshots as SVG;
  - lists of node rows, frozen table rows and bracket matching;
  - a log console in another terminal;
  - more of Textual's stylesheet language: nesting, variables,
    combinators, pseudo-classes and `margin`.

  [The parity audit](../design/textual-parity.md) tracks what is left.
- **Noctiluca for scripts and agents.** It gains:
  - a control socket, so a script or a coding agent can drive a running
    Noctiluca (`noctiluca ls`, `noctiluca action`, `Ctrl+G` to send an
    element to an agent), with a read-only mode;
  - the mouse, to the pixel on terminals that report pixels;
  - video at up to 30 fps, and a full-pixel view that re-sends only the
    tiles that changed;
  - `--ssh HOST`, which browses another machine's network through an SSH
    tunnel, and `--split`, which opens a pane beside the terminal;
  - `--transparent`, and an animated start page.

  The real-site gallery's layout bugs are fixed: captions, hidden text,
  blank rows, settling and lazy pictures.
- **`inspect` for Rust values.** `rich_ext::inspect` is upstream's
  `rich.inspect` report, and `#[derive(Inspect)]` writes it for your types.
- **Animated banners.** FIGlet text with an effect: `rich banner --effect`.
- **AVIF**, opt in: the `avif` feature of rs-rich-art, the CLI and Noctiluca
  (it links libdav1d).
- **The stable set's groundwork:**
  - **edition 2024** for every crate, with resolver 3 and a written MSRV
    policy;
  - **a threat model** and a security policy (`SECURITY.md`), with private
    vulnerability reporting;
  - **a hardening round** from its review (below);
  - **the signer pushes as a GitHub App**;
  - **a call for the first community plugin**: a WASM plugin template, a
    [guide page](../guide/write-a-plugin.md) and
    [#831](https://github.com/buchochelliq-labs/rs-rich-cli/issues/831).
- **The docs build with Zensical**, Material for MkDocs' successor.

A default build of `rs-rich` still renders exactly like upstream `rich`
15.0.0.

## Migration

Breaking changes in 0.0.x crates (the
[CHANGELOG](https://github.com/buchochelliq-labs/rs-rich-cli/blob/main/CHANGELOG.md)
has each, and `api/semver-breaks.toml` lists them with their reasons):

- **Edition 2024 and the MSRV.** Every crate is on edition 2024, which
  needs Rust 1.85 or later; the declared MSRV (1.90, 1.91 for lumis) is
  unchanged. The policy is in `docs/BRANCHING.md`.
- **rs-rich-interact: `Mouse` has a `pixel` field.** A `Mouse` built with
  a struct literal needs `pixel: None`.
- **rs-rich-intuituive: `Easing` is `#[non_exhaustive]`.** A `match` on it
  needs a `_` arm. `TableOptions` gains `freeze_rows`.
- **noctiluca:** `Args`, `Options`, `Config` and `ChromeOptions` gain
  fields (the mouse, `--transparent`, `--ssh`, `--split`, agent control),
  `Command` and `PageAction` gain variants, and `Run` no longer derives
  `Eq`.
- **The CLI's `rich URL`** sanitizes what it fetches by default
  (`--no-sanitize` keeps the old output) and refuses an https→http
  redirect: DIVERGENCES §50.
- **`rich serve` bound to every interface** checks the `Host` header
  against its allow-list; add a LAN name with `--allow-host`.
- **`rich console`'s default socket** moved to `console/console.sock` in
  intuiTUIve's state directory, and it is Unix only for now.

## Release test

- **The release gate** (`scripts/validate_release.py --tag release-0.0.24`)
  on `main` at `c2d65880` with the notes on top (docs and one test), in a
  Linux container on Rust 1.99, passed: fmt; clippy `-D warnings` with
  default features, `--all-features`, and the CLI without default
  features; `cargo test --all`, the CLI without default features and the
  plugin loaders (7,262 passed, 22 ignored, none failed); the five release
  script suites; the version tables, `RELEASES.toml` and the CLI reference
  up to date; `cargo check --workspace --locked`; `check_packages.py`
  (every crate packaged and verified); `release.py plan release-0.0.24
  --semver-checks` selecting all 21.
- **The golden fixtures** regenerate byte for byte from rich 15.0.0, in a
  virtualenv with only `rich` 15.0.0.
- **The docs tapes:** all 77 tapes, 299 screenshots, match with a release
  build of the CLI and the examples, built with CI's features.
- **The docs:** `zensical build --strict` for both sites, and
  `check_site_links.py` finds every relative URL.
- **CI:** the release PR (#844) ran the full gate on this tree: the
  feature matrix, the live browser job, the macOS and Windows jobs, MSRV,
  the API and SemVer job, the tapes and the benchmark gates.
