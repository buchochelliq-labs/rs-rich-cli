# 0.0.21 cohort: widgets, text editing and a playground in the docs

![Memo celebrating, trunk up, with confetti cells](../assets/intuituive/mascot/elephant-celebrate.svg){ .tui-mascot width="128" }
**Published on 2026-10-21**, every crate by one release run, with `rs-rich`
0.0.9 on PyPI (uploaded early on 2026-10-22, UTC). See
[Publication](#publication).

0.0.21 fixes what the demo loop's seventh round found and adds what the
clones and a consumer asked for: stock form controls, a log pane fed by
`tracing`, text editing with Emacs and Vim keys, effect presets, new charts,
Huh-style forms, Mermaid sequence and ER diagrams, and `Syntax` and
`Markdown` without syntect. The docs gain a playground: guide blocks, CLI
examples and whole apps run in the reader's tab. rs-rich has a mark of its
own, and intuiTUIve a section of its own with Memo, its mascot. The
[0.0.21 plan](../plans/0.0.21.md) says what moved on to 0.0.22.

- **Round 7's four bugs, fixed.** The focus after a modal, a styled
  `layers` node covering its children's gaps, `layout::squarify` keeping the
  largest tile, and a text box keeping its keys inside a `previews_keys`
  container. The clones lose their workarounds.
- **csv's million-row filter is fast again.** `TableSource::rows` reads in
  bulk and `rich_ext::transform::Pattern` runs a regex on a `&str`: 15.4 s
  to 3.8 s in the unoptimised build (2.3 s to 0.27 s in release).
- **Form controls.** `button`, `checkbox`, `switch_toggle`, `radio`,
  `slider`, `select_field`, `collapsible` and `spinner` (with
  `loading_when`), with roles and values for assistive technology. See
  [Buttons and form controls](../guide/intuituive/controls.md).
- **Logs in a pane.** intuiTUIve's `Log` keeps a scrollback, follows the
  newest line, filters by level, target and query, and has a targets panel;
  the off-by-default `tracing` plugin feeds it from the app's own events
  through rs-rich-ext's new `ChannelSink`.
- **Text editing.** A kill ring, search with a find bar, word wrap, tabs,
  an undo limit and caret shapes; rebindable keys with Emacs and Vim
  presets (Vim behind a `vim` feature). See
  [Editing text](../guide/intuituive/text-editing.md).
- **Effect presets.** intuiTUIve's `fx` module: fades, dissolve, sweep,
  slide, glitch, rain, shimmer and skeleton placeholders, composed in
  sequence or in parallel, played once, on a condition or as a
  transition, and straight to their end in accessible mode.
- **Charts, QR codes and gradients.** `PieChart` (and donuts), stacked bars
  and areas, `QrCode` behind the new `qr` feature, and `GradientText`;
  `rich chart --kind pie` and `--kind stacked`. See
  [Charts](../guide/ext/charts.md).
- **Huh-style forms and `rich spin`.** `Form` gains multi-select, notes,
  descriptions, file and dynamic-choice fields and pages over a new
  `Paginator`; `rich spin -- COMMAND` runs a command under a spinner, after
  `gum spin`.
- **Mermaid sequence and ER diagrams, drawn as text**, and labels at an
  edge's ends in rs-rich-diagram (DOT's `taillabel` and `headlabel`).
- **For ODS, a consumer's review.** rs-rich-ext writes renderables as
  GitHub Markdown ([Markdown for GitHub](../guide/ext/markdown-export.md)),
  takes plain-text table cells, and highlights SQL with no syntect. Core's
  new `code` feature renders `Syntax` and `Markdown` without syntect
  ([Divergences #39](../DIVERGENCES.md)), and `Table`, `Panel`, `Rule` and
  `Markdown` gain read-only getters that mirror upstream's attributes.
- **No DevTools port on Linux and macOS.** rs-rich-embed's Chrome engine
  speaks DevTools over a pipe there; Windows keeps the port, still a
  [known limit](../known-issues.md#chromes-devtools-port-on-windows-in-rs-rich-embed).
- **The marketplace's listing format.** A JSON Schema, a validator in CI
  and a [design note](../design/marketplace.md); rs-rich-plugin-api exposes
  the checks a resolver makes against the host's plugin API and ABI. The
  crate that resolves and installs, and `rich plugin`, are 0.0.22's.
- **A playground in the docs.** **Try it** on guide blocks (rs-rich in
  wasm), a terminal for CLI examples (`rich` on WASI), and **Run it** for
  `choose`, `filter`, `pager`, `explore` and four intuiTUIve apps. See the
  [Playground](../playground.md).
- **Builders are `#[must_use]`** in every crate but the mirror, so a
  dropped builder warns.
- **rs-rich's own identity.** A mark, favicon, wordmark, section icons and
  hero in gold; intuiTUIve as a top-level section with its own mark, a
  [widget index](../guide/intuituive/widget-index.md), and Memo and Tui.

A default build of `rs-rich` still renders exactly like upstream `rich`
15.0.0: the `code` feature only changes a build without syntect, and the
getters only read.

## Migration

Breaking changes in 0.0.x crates (the
[CHANGELOG](https://github.com/buchochelliq-labs/rs-rich-cli/blob/main/CHANGELOG.md)
has each):

- **`rich_interact::Value` gains `List` and `Path`.** An exhaustive `match`
  on it needs the two arms; `Answers` gains `list` and `path`. In Python, a
  form's path answer is a `pathlib.Path`.
- **`rich_diagram::Edge` has two new public fields**, `start_label` and
  `end_label` (`Option<String>`): a struct literal names them (`None` for
  none), or start from `Edge::new(from, to)` and set the fields you need.
- **Builders are `#[must_use]`.** Nothing stops compiling, but a dropped
  builder, or a dropped setter on a `Copy` handle such as
  `Transport::tick` or `Timer::max_catch_up`, now warns
  (`unused_must_use`). A handle's setter still makes its change: write
  `let _ =` to keep the old behaviour without the warning. Under
  `-D warnings` the warning is an error.
- **Builds without default features.** The defaults are unchanged, but
  what a feature turns on moved:
  - core's `markdown` turns on the new `code` feature, not `syntax`: with
    `default-features = false`, add `syntax` for syntect's highlighting in
    code blocks. rs-rich-ext forwards the same split (`code`, `syntax`,
    `markdown`; `sql` turns on `code`).
  - rs-rich-interact, rs-rich-intuituive and rs-rich-web have a new
    default `syntax` feature: a build without default features leaves syntect out unless it
    names `syntax`.
  - rs-rich-web's serving code (`serve`, `serve_command`, `Server`, the
    page, the session processes) is behind the new default `server`
    feature.
- **Behaviour:** with nothing focused, the arrow keys scroll a scrollable
  `Log` under the pointer; without a terminal, `rich spin` runs the command
  with its output let through.

## Release test

- **The release gate** (`scripts/validate_release.py --tag release-0.0.21`)
  on `main` at `c25f65e` with the notes on top, in a Linux container: fmt;
  clippy `-D warnings` with default features, `--all-features`, and the CLI
  without default features; `cargo test --all` (5,548 passed, 8 ignored,
  none failed), the CLI without default features (545 passed) and the
  plugin loaders (29 passed); the four release script suites (142 tests);
  the version tables, `RELEASES.toml` and the CLI reference up to date;
  `cargo check --workspace --locked`; `check_packages.py` (all 17 crates
  packaged and verified); `release.py plan release-0.0.21` selecting all 17.
  The tests were built without debug info, as the container's disk could
  not hold a debug build of the workspace's tests.
- **The golden fixtures** (34 files, 4,561 cases) regenerate byte for byte
  from rich 15.0.0.
- **The docs tapes:** all 67 tapes, 253 screenshots, match with a release
  build of the CLI and the examples, built with CI's features.
- **The docs:** `mkdocs build --strict` for both sites.
- **The declared MSRV:** CI's checks on Rust 1.90 (the workspace with
  every feature, and the CLI with CI's features) and on 1.91
  (rs-rich-lumis, and the CLI with every feature).
- **CI on #764's head** (`22718fd`, which holds #763 too): 68 checks
  passed, including the feature matrix and the macOS and Windows jobs this
  pass did not run.

### Not in this release

The plan's larger workstreams were not started in this cohort, and move to
0.0.22 with the marketplace's commands:

- **Parity** (workstreams 3 to 6): the partial rows of
  [PORTING](../PORTING.md), `scope.py`, the divergences' verdicts and the
  differential fuzzer's new renderers.
- **The `rs-rich-marketplace` crate** (resolving, downloading, the
  lockfile); only the listing format and the host's version checks shipped.
- **The gaps three clones share** (workstream 2) and a re-run of the
  clones against it.
- **The recorder's frame rate on macOS**, the APNG default (still an open
  decision) and **rs-rich-doom** on the 0.0.20 crates.
