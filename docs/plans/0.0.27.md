# 0.0.27 plan: Noctiluca's video smooth, the browser recoverable

**Status:** planned on 2026-11-11, after 0.0.26's publication. Main
carries the 0.0.27 versions (every package one patch past 0.0.26). It is
the point release the [0.0.26 plan](0.0.26.md) (decision 5) puts before
0.1.0, the API review of the [plan to 1.0.0](1.0.0.md)'s stage 3.

**Target: about 18 November 2026** (proposed). 0.1.0 then moves to about
25 November; the later dates follow it by the same week.

## Decisions

The maintainer's calls (2026-11-11):

1. **The old release path retires now.** 0.0.26 was the first release rab
   published in full, so `RELEASES.toml`, `release_cohort.py` and
   `pypi-release.yml` go (`docs/BRANCHING.md`, "Which path is current"),
   and `pypi-release.yml`'s trusted publisher is removed from PyPI.
2. **0.0.27's scope is what 0.0.26 moved on, plus three things the
   maintainer saw:** video playback that jitters a little and flickers,
   Amazon still not right, and "the browser has gone" reported at times.
   [The findings](../design/noctiluca-0027-findings.md) (2026-11-11) give
   their causes.

Open, for the maintainer:

- **Chrome's user agent.** Headless Chrome announces itself as
  `HeadlessChrome/153`, and nothing overrides it; Amazon's "unsupported
  client" page (seen in #878's review) fits that. Dropping "Headless" from
  the user agent is a one-line change, but it is a policy call: Noctiluca
  would no longer say it is headless.

## What is in it

### 1. Video: smooth frames, no flicker

From [the findings](../design/noctiluca-0027-findings.md#1-video-jitter-and-flicker),
measured on a debug build (re-measure on release before quoting):

| Fix | Cause it removes | Size |
|---|---|---|
| Upload a Kitty frame's image before the cells that name it | The cells switch to a new image id before it exists, then the old one is deleted: a blank frame where synchronized output is off (737 of 738 frames) | S |
| For an opaque live picture in iTerm2 and Sixel, skip the half-block repaint and the erase | Every frame drew half blocks, erased, then drew the image (all frames) | M |
| Readings off the tab's thread (the reader thread 0.0.26 moved on) | A reading holds the tab for 150 to 230 ms about once a second: every gap of 200 ms or more (19 to 25 in 23.5 s) | L |
| Keep a playing video inside Chrome's view when following Noctiluca's scroll | One row of scrolling can leave the video's top outside Chrome's view, dropping the screencast area: frames fall back to screenshots at 4 to 5 a second for 5 to 20 s | S–M |
| Pace frames from the video's own timestamps | A fixed 33 ms clock gives 24 and 25 fps video an uneven cadence | M |
| Decide frame drops in one place, at the tab | iTerm2 and Sixel drop unevenly (540 frames in, 352 out, a mix of 33 and 66 ms holds) | S |

Done when: on the watch-page fixture, frame intervals in Kitty have a p95
within twice the frame period and no gap over 120 ms outside navigation;
no frame blanks its region in any protocol (counted from the trace); and
#883's gate still passes 3 of 3 in iTerm2, Kitty and ANSI.

### 2. The browser: recoverable, and said once

From [the findings](../design/noctiluca-0027-findings.md#3-the-browser-has-gone):
"the browser has gone" means the DevTools connection's thread ended. Chrome
exiting is the only cause reproduced; a renderer crash instead freezes the
tab silently for 30 s per call.

| Fix | Size |
|---|---|
| Say the cause once (Chrome exited, its connection closed, it did not start), not a toast per command | S |
| Restart Chrome and reopen the page, keeping the tab's history | M |
| A renderer crash fails pending calls at once and offers a reload | M |
| Check a detach event against the page's own session before ending the connection | S |
| End the Chrome left running after the start timeout | S |
| Shorter timeouts for the tab's periodic calls (readings, media state) | S |
