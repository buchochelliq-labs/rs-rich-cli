# 0.0.26 plan: Noctiluca made steady, before the API review

**Status:** published on 2026-11-11 ([the release notes](../releases/0.0.26.md#publication)).
Every crate and `rs-rich` 0.0.14 on PyPI went out from `e5422bf9` (#894's
merge, rab v2.1.2) in one release run, the first in which rab uploaded to
PyPI itself. The commit after these notes opens 0.1.0 again. Not recorded
before the tag: the Cornacai run with a real agent (moved to 0.0.27).
0.0.27 follows (decision 1's point release), with what the real-site check
found (#889 to #892).

**Target: about 13 November 2026.** 0.1.0, the API review of
[stage 3](1.0.0.md#stage-3-api-review-and-stability-tooling-010), moves
to about 20 November (decision 16).

## Decisions

The maintainer's calls (2026-11-10):

1. **One more release before 0.1.0.** 0.0.26 ships what merged after
   0.0.25 (#877, #878, #886) with the fixes it needs, so the API review
   starts from a steady base. Recorded in the 1.0.0 plan as an amendment
   to decision 15.
2. **#883 is fixed first.** #878's own
   [performance qualification](../design/noctiluca-performance-qualification-f309073.md)
   found the iTerm2-compatible gate failing in 3 of 3 runs (Kitty and ANSI
   3 of 3). 0.0.26 is not tagged until that gate passes 3 of 3 runs with
   its thresholds and workload unchanged, with Kitty and ANSI still 3 of 3.
3. **Noctiluca plays sound by default.** Chrome was started with
   `--mute-audio` unless `--audio` was given. From 0.0.26 sound is on
   when Noctiluca runs locally, and off over SSH (where the browser's
   sound would play on the far machine) unless `--audio` is given; a flag
   turns it off.
4. **Everything named before the tag is fixed** (2026-11-10): #883 first,
   then the nightly parity job, the by-hand checks, #884 and the
   `WrapActionLabels` ordering (below), none left as optional.
5. **Another point release, 0.0.27, follows 0.0.26** before 0.1.0. Its
   scope is set once 0.0.26 is out, from what 0.0.26 moves on.

## Versions

Main's manifests say 0.1.0. The release PR moves every package of
`RELEASES.toml` to the patch after its 0.0.25 version (`rs-rich-cli`
0.0.26, `rs-rich` 0.0.16, `noctiluca` 0.0.5, and so on, with `rs-rich`
0.0.14 on PyPI), its internal requirements and lockfiles with it, as the
0.0.25 cohort did; `release_cohort.py sync` and rab's `sync` carry them.
Breaking changes since 0.0.25 (`Cell.width`) are in
`api/semver-breaks.toml`. After publication, the follow-up records it and
opens 0.1.0 again, as #853 did.
