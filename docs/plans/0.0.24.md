# 0.0.24 plan: the apps track, the stable set's groundwork, and the docs on Zensical

**Status:** planned on 2026-11-01. 0.0.23 was published on 2026-10-27,
and the 0.0.24 versions are open (see [Versions](#versions)). On
2026-10-27 the maintainer set the course to 1.0.0: 0.0.24 opens the
[two tracks](1.0.0.md#before-010-the-apps-and-the-wider-stable-set-0024-to-0028)
that run to 0.0.28. On 2026-11-01 the maintainer made the calls in
[Decisions](#decisions) and approved this plan; work goes in four waves
(see [Order of work](#order-of-work)). It belongs to the stage before
0.1.0 in the [plan to 1.0.0](1.0.0.md).

Earlier, on 2026-10-25 and 2026-10-26, 0.0.24's first items were folded into
[0.0.23](0.0.23.md): Noctiluca's video (0.0.23's item 4), `best` as the
default paint strategy (item 5), the third wave's hand-ons (items 9 to 14)
and the marketplace's official keys (item 16).

## Workstreams

### Track 1: the apps

#### 1. Cornacai, all four phases (#794): acp (new), cornacai (new)

A Toad-inspired front end for coding agents over the Agent Client Protocol.
Toad is AGPL: its source is never read, and Cornacai is written clean-room.

- **Phase 1:** `docs/design/cornacai.md`. It covers the scope, the crate
  split, and how the app maps onto intuiTUIve and rs-rich-embed's `PtyHost`.
- **Phase 2: `rs-rich-acp`.** An ACP client over JSON-RPC on stdio, with
  no terminal code. It covers:
  - initialize, session/new and prompt;
  - the streamed session updates;
  - permission requests;
  - the file-system and terminal capabilities the client offers.

  Its tests replay recorded transcripts. An example drives a real agent
  when one is installed, and skips otherwise.
- **Phase 3, the app:** streaming Markdown, `@` mentions, permission
  prompts, a diff view and one session. In wave 3, once its parity items
  have merged.
- **Phase 4:** a shell pane, several sessions, an `agent` kind in the
  marketplace, and the guide.
- **Both crates are new:** first versions upload with the environment's
  token, and they get API snapshots and PORTING prose.

### Track 2: the stable set's groundwork

#### 7. Edition 2024: every crate (first, alone)

- **What moves:** the workspace and every manifest outside it: the Python
  bindings, the fuzz targets, the playground and its spike, the plugin
  examples, the tape fixture project, the prototypes and the app template.
- **How:**
  - `cargo fix --edition` and `resolver = "3"`.
  - Review by hand what `cargo fix` rewrote: `impl Trait` captures,

- **Gates:** goldens and tapes stay byte for byte the same. API snapshots
  change only for edition noise, and each change is explained.
- **The MSRV policy is written down:** the latest stable minus six, and
  raising it is a minor release.
