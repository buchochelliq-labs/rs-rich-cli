# 0.0.24 plan

**Status:** started on 2026-10-26 with what [0.0.23](0.0.23.md)'s third
wave handed on, all of it the maintainer's call that day. On 2026-10-25
the maintainer had folded 0.0.24's first items into 0.0.23: Noctiluca's
video (now part of 0.0.23's item 4) and `best` as the default paint
strategy (0.0.23's item 5). More is filled in once 0.0.23's cohort is
tagged.

## Handed on from 0.0.23

### 1. Sound in tapes: record, intuituive, cli

Doom's gap 13 ([the gaps doc](../design/doom-core-gaps.md#13-sound-in-recordings-rs-rich-record)),
option (a), the maintainer's choice on 2026-10-26.

- **An environment contract.** The recorder sets
  `RICH_RECORD_AUDIO=<path>` for the program it records. intuiTUIve's
  `output()` sees it and opens a null output (gap 9's
  `OutputOptions::null`) tapped to that file (`Output::tap`,
  `Tap::to_wav`), with its start put on the recording's clock.
  rs-rich-record still does not depend on intuiTUIve.
- **The tape side.** `Set Audio on` in a tape, or `rich record --audio`.
  MP4 output carries the sound as AAC, in sync with the frames'
  timestamps. Outputs with no sound track (GIF, APNG, the HTML player)
  get a WAV beside them.
- **Acceptance:** the gaps doc's test. A tape running a program that plays
  a 1 s 440 Hz tone from its second frame produces an MP4 whose tone
  starts within one frame of that frame and lasts 1 s, ±1 frame.

### 2. Palette Sixel for pictures of 256 colours or fewer: art

Doom's gap 2 left `Picture`'s Sixel path quantizing. Using
`sixel::encode_palette` there for frames of 256 colours or fewer keeps
their colours exactly, but it changes the Sixel bytes of pictures already
in tapes, so the maintainer deferred it here on 2026-10-26. It lands with
the tapes it changes re-recorded and the change named in the release
notes. (`ImageView::aspect`, `cell_px` and `keep_last_row`, from gap 1's
proposal, were dropped, not deferred.)

### 3. rs-rich-ext's `Surface` on `best`: ext

0.0.23 made `best` intuiTUIve's default paint strategy. rs-rich-ext's
`Surface` keeps its own default for now; it moves to `best` here, with
the paint benchmark showing it no slower on the surface's scenes.

### 4. `Progress.log`: rich

`Console.log` is ported (0.0.23's console item), so `Progress.log`, which
calls it, can be. Golden cases from rich 15.0.0, as for the console.

### 5. `Live` calls `set_live`: rich

0.0.23 ported `Console.set_live`/`clear_live`, but a `Live` here owns its
console (DIVERGENCES §17) and does not use the live stack. Make `Live`
push itself on its console's stack and clear it on stop, as upstream
does, so a live display started inside another one nests as it does
upstream.

### 6. The CLI demo shows the new console: cli

Update `rich --demo` for what 0.0.23's console port added (`log` with its
time and path columns, recording and its exports, `status`), as
upstream's own demo shows them.
