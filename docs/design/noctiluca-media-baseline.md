# Noctiluca media baseline (2026-11-08)

Source: `7fcdbf7263f81d89c2975a47ee4761b4a0e1c7cc`; Rust 1.90.0; Linux x86_64. Builds use `/workspace/work/toolchain/env.sh` (test and dev debug info disabled, incremental off). The fixture controls in `stream-with-log.html`, `gauge-{canvas,svg}.html`, `lazy.html`, and opt-in `product-grid.html?quality` make keyed chat changes, independent gauge values and reserved versus intrinsic image loading repeatable without external services. `?quiet` stops gauge timers; `window.setGauge` drives them. The existing stream's `?quiet` stops its message timer.

Saved-snapshot and Driver tests exercise projection, log scrollback, an overlay, scrolling, and resize without Chrome. A gated resource test queues navigation before submitting an old image to the decoder and observes the new page for 500 ms. It cannot prove that the decoder completion was consumed within that window. These checks do not prove terminal placement cleanup, actual presented frames, focus/drafts, or native terminal behavior. The input's row/column and cell-metric matrix and the complete A/B/C interactions still require browser and terminal runs. A deterministic private-worker test of completion after invalidation is still needed.

The pre-change focused command `cargo test -p noctiluca --test pictures --test layout --test logs --test live_logs --test video_app -- --nocapture` yielded 37 browser-free passes; all six `live_logs` cases self-skipped because `RICH_EMBED_CHROME` was unset, despite the Rust harness labeling them passed. File URLs were blocked by browser policy. Prior workspace verification also found existing `nonminimal_bool` clippy errors in the faithful core and exhausted disk while linking the full test suite; these are not evidence about media behavior.

`cargo test -p noctiluca --test media_quality -- --nocapture` passed three tests. A first removal test manually cleared a media array while retaining block references and panicked with an index out of bounds; this invalid model was removed and is not evidence of a product regression. No production fix is selected yet: projection checks alone do not establish a lifecycle failure or quantify the suspected costs. Instrument layout calls, encoding and actual presentation across scrolling, lazy loads, video, chat and combined work; establish stale-completion and placement regressions before choosing changes. Native Kitty, Ghostty, WezTerm, iTerm2 and Sixel runs, including SSH/multiplexer conditions, remain unverified.

A short release harness sample ran on an Intel Xeon Platinum 8573C, Linux x86_64, 5 visible CPUs: `NOCTILUCA_BENCH_SECONDS=1 cargo test -p noctiluca --release --test video_bench -- --ignored --nocapture`. This uses 100×40 cells, a saved `video.html` snapshot and synthetic 800×720 viewport frames, with a one-second measurement per configuration after warmup. Cells at the guessed bandwidth and 30 offered fps emitted 30 updates/s and 39 kB/s (p95 inter-update gap 35.2 ms); Kitty at the fast 32 MiB/s budget emitted 30 updates/s and 6,346 kB/s (p95 35.0 ms); Sixel at that budget emitted 30 updates/s and 5,016 kB/s (p95 41.9 ms). These output counts and spacing are not input-to-presentation latency or proof of native display. One-frame isolated encoding measurements were 6.26 ms Kitty, 30.77 ms Sixel, and 7.19 ms iTerm2 for a 60×15-cell region. One-second samples are exploratory, not release thresholds. Raw output is in `/workspace/work/noctiluca-media-baseline/video-release.log` on the measurement host.

Layout call counts, end-to-end latency, queue depth, retained bytes, actual frame presentation and scrolling, lazy-loading, chat and combined-workload measurements remain unmeasured.
