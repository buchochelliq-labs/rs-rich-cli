# CLI 0.0.9 implementation plan

> **For agentic workers:** Use executing-plans for implementation and dispatching-parallel-agents for the isolated art, config, batch, and demo/doctor modules. Parent integrates the binary boundary and reviews combined behavior.

**Goal:** Deliver the five approved usability items and the bounded #125 image-quality feature.

**Architecture:** Core remains unchanged. CLI composes public APIs for named config themes, batch status/cancellation, selective demos, and read-only diagnostics. Art owns reusable opt-in ANSI256 quantisation and Floyd–Steinberg dithering.

**Tech Stack:** Rust 1.90, existing TOML/config/ctrlc/tempfile dependencies, Python PTY regression and recording tools, MkDocs.

**Spec:** User-approved six-item release proposal in this session; concrete contracts below.

## Global constraints

- Independent versions: CLI 0.0.9, art 0.0.7; core 0.0.4 and ext 0.0.6 unchanged unless an actual source change requires their own bump.
- No core renderer behavior changes. No publication or tags during preparation.
- Existing output is unchanged unless a feature is opted into, except human batch progress on an interactive terminal.
- Piped stdout remains rendered content; JSON report stderr remains exactly one JSON report. Terminal progress must not corrupt either contract.
- Quantisation: ANSI256 palette, deterministic nearest-colour mapping; optional Floyd–Steinberg diffusion after fitting/compositing/sizing and before glyph selection. Truecolor/no-dither defaults preserve existing pixels. Start with ASCII and half-blocks; unsupported mode/option combinations must be rejected rather than silently ignored.
- Theme definitions are validated data mapped to public rich::Theme; CLI/profile/default precedence is deterministic. Workers receive the resolved theme snapshot.
- Doctor describes detected versus inferred capabilities and never probes the terminal, launches a pager, or fetches a URL.
- Demo sections are stable names, listable and validated before playback; redirected output stays finite and interruption cleanup remains intact.

## Review focus

1. Theme names and style strings in inactive profiles, option-looking values and worker propagation.
2. Ctrl+C during batch planning/running/replay; all started workers must be reaped and inputs remain intact.
3. Doctor with malformed config, NO_COLOR, redirected output and absent pager; no sensitive environment dump.
4. Dithering at transparent edges, tiny/odd dimensions and fitted cell grids; disabled-option output parity.
5. Demo section selection in lean builds, list-only invocation and Ctrl+C in both pipes and terminals.

## Tasks and interfaces

### 1. Named themes
Files: config.rs and config/theme regression tests; parent wires main.rs.
Contract: TOML [themes.NAME] maps style names to style strings. defaults/profile `theme` and `--theme NAME` select it. Resolved bindings become repeated `--theme-style NAME=STYLE` arguments, which main validates and applies via Theme before render/export. This also snapshots bindings for batch workers. Config show exposes selected theme. CLI bindings override configured bindings.
- [x] Add failing tests for selection, invalid styles/references, inactive definitions, precedence and worker-equivalent argv.
- [x] Implement strict parsing and style validation; reuse existing config discovery and merge logic.
- [x] Wire theme construction into normal, streaming and export consoles; preserve no-config and NO_COLOR semantics.
- [x] Verify default/profile/explicit themes through real CLI output and HTML/SVG export.

### 2. Batch progress and cancellation
Files: batch.rs and new batch process tests; parent adds Cli.progress and parser/help.
Contract: `--progress` / `--no-progress`, default enabled only when stderr is a TTY and report is human. Print completed/failed/total status on stderr. Install the batch Ctrl+C handler only from the actual main entry for batch commands, not nested demo calls. Expose install_interrupt_handler() for parent wiring. Cancellation stops scheduling, kills and waits active subprocesses, returns 130, and emits one structured interrupted report when requested.
- [x] Write failing process tests for progress gating and cancellation while workers are active.
- [x] Implement cancellation checks at planning/scheduling/replay boundaries and ensure worker cleanup on every exit.
- [x] Preserve deterministic replay and collision/input alias protection.
- [x] Verify serial/parallel success, failures, cancellation, no leftover workers and no input changes.

### 3. Selectable demo and doctor
Files: demo.rs, new doctor.rs and dedicated tests; parent owns main.rs integration.
Contract: `--demo-list` lists `core`, `workflows`, `art`; `--demo --demo-section NAME` plays one group. Existing full tour remains default. Doctor provides human output and `--report json`: package/build features, stdout TTY/size/colour, inferred Sixel support/selected image mode, selected config/profile and pager choice, without executing it. Return actionable config errors via existing usage/report contracts.
- [x] Add failing tests for list, valid/invalid sections, option operands and lean art section.
- [x] Factor existing tour into sections without duplicating rendering or cleanup.
- [x] Add doctor tests for redirected output, NO_COLOR, malformed config and JSON validity.
- [x] Parent routes doctor in main, extends value-option recognition and updates generated help.

### 4. ANSI256 and Floyd–Steinberg (#125 slice)
Files: rich-art colour preprocessing module, image_art.rs integration, exports and tests; parent wires CLI.
Contract: public ImageColorMode::{TrueColor,Ansi256} and Dither::{None,FloydSteinberg}, ImageArt::color_mode and ::dither builders (or communicate exact alternative API before integration). CLI `--image-color truecolor|ansi256` and `--image-dither none|floyd-steinberg`; dithering requires ANSI256 and ASCII/blocks. Keep ImageOptions struct source compatibility by private builder fields.
